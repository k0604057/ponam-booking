# 정밀 스펙 #3 — 33m2 크롤러

> **이 문서가 원본이다.** 채팅으로 주고받은 초안이 아니라 여기를 기준으로 한다.
> 실제 구현하며 알게 된 것은 「실제 구현 노트」에 모아뒀다 — 초안만 보고 고치면 다시 깨지는 것들이다.
>
> 시크릿은 `~/.ponam.env` 에만 있다. 채팅·코드·커밋에 값을 쓰지 않는다.

상태: **완료** (2026-08-17). 선행은 [02_정밀스펙_초기셋업.md](./02_정밀스펙_초기셋업.md).

## 1. 목표

33m2 호스트 계정의 계약(=예약) 정보를 하루 두 번 자동 수집해 Supabase 에 반영한다.
퇴실일 기준 청소 일정은 DB 트리거가 알아서 만든다.

## 2. 사전 조사 결과

공개 JSON API 없음. 호스트 웹(`web.33m2.co.kr`)은 Next.js App Router 서버 렌더링이라 예약 데이터가
HTML 에 실려 온다. 네트워크에 잡히는 XHR 은 Datadog·GA·카카오 픽셀뿐이다. **따라서 Playwright 로 DOM 을 읽는다.**

| 용도 | URL |
|---|---|
| 계약 목록 (전체) | `https://web.33m2.co.kr/host/contract` |
| 상태 필터 | `?status=REVIEWING\|READY\|ACTIVE\|TERMINATING` |
| 액션 필터 | `?actionType=WAITING_APPROVAL\|WAITING_CHECKIN\|WAITING_CHECKOUT\|WAITING_CHECK_FINISH` |
| 계약 상세 | `/host/contract/{계약번호}` |
| 입퇴실 일정 | `/host/contract/{계약번호}/schedule` |
| 로그인 후 진입점 | `/host/main` |

목록 카드의 상세 링크는 `a[href^="/host/contract/"]` 이고 끝이 숫자다.
`.../schedule` 로 끝나는 링크도 같이 잡히니 **정규식 `^/host/contract/(\d+)$`** 로 걸러야 한다.
계약번호가 곧 `reservations.external_id` 다.

방 목록(`/host/room`)은 방 ID 가 링크로 노출되지 않으므로(전부 버튼) 긁지 않는다.

## 3. 매핑

| 33m2 | 우리 스키마 |
|---|---|
| 계약번호 | `reservations.external_id` |
| 입주일 / 퇴실일 | `reservations.checkin_date` / `checkout_date` |
| 상태 뱃지 | `reservations.status` (아래 표) |
| 임차인 이름 / 연락처 | `reservation_private.guest_name` / `guest_phone` |
| 파싱한 원본 전체 | `reservation_private.raw` (jsonb) |
| 이용 금액 | `reservation_finance.gross_amount` |
| 계약 수수료 (절댓값) | `reservation_finance.platform_fee` |
| 최종 정산 금액 | `reservation_finance.net_amount` |
| 임대료·관리비·청소비·환불액·정산일·정산상태 | `raw` 에만 |

상태 매핑:

| 33m2 뱃지 | `reservation_status` |
|---|---|
| 계약대기 / 입주대기 / 거주중 / 퇴실중 | `confirmed` |
| 계약종료 | `completed` |
| 취소 / 결제취소 | `cancelled` |

부분일치 함정 — **`결제취소` 를 `취소` 보다 먼저 검사해야 한다.**

`checkin_time` / `checkout_time` 은 33m2 가 고정 시각을 주지 않으므로 `null` 로 둔다.
`/schedule` 의 `거주중 2026.08.15 18:40` 은 **실제** 입주 시각이라 예정 시각이 아니다 → `raw.timeline` 에만 넣는다.

## 4. 숙소도 크롤러가 만든다

수동 등록은 없다. (초안의 "SQL 로 한 건 수동 INSERT" 는 폐기됐다.)

계약 상세에 방 이름과 지번 주소가 둘 다 있으므로 `properties` 를 자동 생성한다.

**키는 지번 주소다. `properties.external_id = 지번 주소.`**
방 이름은 호스트가 언제든 바꾸는 홍보 문구라 키로 불안정하다.

계약 1건 처리 시:

1. `properties` 에서 `external_id = 지번주소` 조회
2. 있으면 → `name` 이 달라졌을 때만 갱신
3. 없으면 → insert (`name` = 방 이름, `address` = 지번 주소, `external_id` = 지번 주소)
4. 그 `property_id` 를 예약에 쓴다

**지번 주소를 못 찾으면 그 계약은 실패시킨다.** 도로명 주소로 대신 키를 잡으면 같은 숙소가
다른 키로 하나 더 생겨서, 바로 그 중복 문제를 코드가 스스로 만들게 된다.

주소가 수정되면 숙소가 하나 더 생기는데 **자동 병합은 하지 않는다.** 잘못 합치는 게 중복보다 나쁘다.
설정 화면에서 사람이 확인하고 합친다.

  upsert.ts                 # DB 반영 + diff 로깅

  parse.test.ts             # 파서 회귀 테스트

`env.ts` 는 초안에 없던 파일이다. `scrape33m2.ts` 는 세션 경로를, `upsert.ts` 는 Supabase 키를
필요로 하는데 둘 다 `run.ts` 에서 가져오면 순환 import 가 된다.

### `crawler/session.ts` — 세션 캡처

**헤드리스로는 로그인을 못 뚫는다.** SSH 아닌 맥 화면 앞에서 한 번 실행한다.

```bash
npx tsx crawler/session.ts
```

- `chromium.launch({ headless: false })` 로 브라우저를 띄우고 `/host/main` 으로 이동
- "로그인을 마친 뒤 이 터미널에서 Enter" 를 출력하고 stdin 을 기다린다
- Enter 를 받으면 `context.storageState({ path: M33_SESSION_PATH })` 저장 후 `chmod 600`

### `crawler/scrape33m2.ts`

```ts
export type ScrapedContract = {
  externalId: string;
  roomName: string;
  roomAddress: string | null;   // 지번 우선, 없으면 도로명
  jibunAddress: string | null;  // properties 의 키. 폴백 없음
  guestName: string | null;
  guestPhone: string | null;    // 형식 검증 통과한 것만. 아니면 null
  checkinDate: string;          // YYYY-MM-DD
  checkoutDate: string;         // YYYY-MM-DD
  status: 'confirmed' | 'cancelled' | 'completed';
  grossAmount: number;
  platformFee: number;          // 절댓값
  netAmount: number;
  raw: Record<string, unknown>;
};

export async function scrape(errors?: string[]): Promise<ScrapedContract[]>
```

동작:

1. `chromium.launch({ headless: true })` + `newContext({ storageState, locale: 'ko-KR', timezoneId: 'Asia/Seoul', userAgent })`
   — **`userAgent` 는 필수다.** 아래 「실제 구현 노트」 1번 참고.
2. `/host/main` 이동 → **HTTP 상태 확인** → 로그인 페이지로 튕기거나 로그인 폼이 보이면 `SessionExpiredError`
3. `/host/contract` 이동, 목록 렌더 대기
4. 페이지네이션 순회 (최대 20페이지에서 중단하고 경고)
5. 각 페이지에서 `^/host/contract/(\d+)$` 링크의 계약번호를 모은다 (중복 제거).
   목록 카드의 뱃지도 같이 담아 상태의 1순위로 쓴다
6. 계약번호마다 `/host/contract/{id}` → 상세 파싱, `/host/contract/{id}/schedule` → 타임라인
7. **요청 사이에 1~2초 랜덤 대기.** 남의 서버다
8. 개별 계약 파싱이 실패하면 그 건만 건너뛰고 `errors` 에 모은다. 전체를 죽이지 않는다

파싱 규칙:

- 금액: `/-?[\d,]+원/` → 콤마·원 제거 → Number → 수수료는 `Math.abs`
- 날짜: `2026년 08월 15일(토)` → `2026-08-15`
- 라벨은 같은 줄의 값을 먼저 보고, 없으면 **다음 줄**을 값으로 쓴다
- 임차인 정보는 `임차인` **정확 일치** 줄 이후 ~ 다음 섹션 헤더 전까지에서만 찾는다
- 연락처는 형식 검증을 통과한 것만 저장한다 (「실제 구현 노트」 3번)
- 상태는 목록 카드의 뱃지를 우선하고, 없으면 상세 값을 쓴다.
  카드 텍스트가 600자를 넘으면 카드 경계를 잘못 잡은 것으로 보고 무시한다

파서는 브라우저 없이 테스트할 수 있게 순수 함수로 떼어 export 한다:
`parseDetailText` `parseKoreanDate` `parseAmount` `normalizePhone` `parseTimeline` `findBadge` `assertHttpOk`

### `crawler/upsert.ts`

```ts
export async function upsertAll(
  items: ScrapedContract[], runId: number, warnings?: string[]
): Promise<{ created: number; updated: number }>
```

- `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` 로 클라이언트 생성 (RLS 우회)
- 계약 1건당:
  1. 숙소 해석 (4절 규칙)
  2. 기존 `reservations` 를 `(property_id, external_id)` 로 조회
  3. 있으면 `checkin_date`·`checkout_date`·`status` 를 비교해 바뀐 필드마다 `reservation_changes` 에 한 줄
  4. `reservations` upsert (`onConflict: 'property_id,external_id'`, `last_synced_at = now()`)
  5. `reservation_private` upsert (`guest_name`·`guest_phone`·`raw`)
  6. `reservation_finance` upsert (`gross`·`fee`·`net`)
- **삭제는 하지 않는다.** 목록에서 사라진 계약도 그대로 둔다
- **청소 일정은 만들지 않는다.** `reservations` 를 쓰면 DB 트리거가 알아서 처리한다

`nights` 는 generated 컬럼이라 넣지 않는다. `first_seen_at` 도 넣지 않는다 — upsert 는 넘긴 컬럼만
SET 하므로 최초값이 보존된다.

### `crawler/run.ts` — 진입점

1. `~/.ponam.env` 로드. 필수 키가 없으면 즉시 종료
2. `sync_runs` 에 `status='running'` 삽입 → `runId`
3. `scrape()`
4. **안전장치: 결과가 0건이면 DB 를 건드리지 않고 실패 처리한다.**
   로그아웃·마크업 변경·차단 시 데이터가 통째로 이상해지는 걸 막는다. **실제로 이게 값을 했다.**
5. `upsertAll()`
6. `sync_runs` 갱신: `status='success'`, `finished_at`, found/created/updated
   (부분 실패·경고가 있으면 성공이어도 `error_message` 에 흔적을 남긴다)
7. 예외 시 `status='failed'` + `error_message`
8. 정상 0 / 실패 1 로 종료

**에러 마스킹** — `error_message` 를 쓰기 전에 `SUPABASE_SERVICE_ROLE_KEY`, `M33_LOGIN_PW`,
`M33_LOGIN_ID` 의 값과 `sb_secret_[A-Za-z0-9_-]+`, JWT(`eyJ...`) 패턴을 `***` 로 치환한다.
`sync_runs` 는 owner/reservation 이 조회할 수 있으므로 토큰이 새면 안 된다.
`error_message` 는 2000자 check 제약이 있어 잘라낸다.

### `crawler/run.sh` — launchd 용 래퍼

launchd 는 PATH 가 빈약하니 node 를 절대경로로 박는다.

```sh
#!/bin/zsh
set -a; source "$HOME/.ponam.env"; set +a
cd "$HOME/ponam-booking" || exit 1
NODE=/opt/homebrew/bin/node
TSX="$HOME/ponam-booking/node_modules/tsx/dist/cli.mjs"
exec "$NODE" "$TSX" crawler/run.ts
```

`npx` 를 거치지 않고 tsx CLI 를 직접 부른다. node 위치가 바뀌면(homebrew 재설치·nvm 전환)
`NODE` 를 다시 맞춰야 한다.

### `~/Library/LaunchAgents/com.ponam.crawler.plist`

- Label: `com.ponam.crawler`
- ProgramArguments: `/bin/zsh -lc "$HOME/ponam-booking/crawler/run.sh"`
- `StartCalendarInterval`: 05:00 과 14:00 두 개 (배열)
- `StandardOutPath` / `StandardErrorPath`: `$HOME/.ponam/crawler.log`

```bash
plutil -lint ~/Library/LaunchAgents/com.ponam.crawler.plist   # 문법 검사
launchctl load -w ~/Library/LaunchAgents/com.ponam.crawler.plist
launchctl start com.ponam.crawler                             # 즉시 시험
launchctl list | grep ponam                                   # 마지막 종료코드
```

맥이 자면 안 돈다: `pmset -g` 로 `sleep 0` / `disksleep 0` 확인.

그다음 데이터 확인:

```sql
select id, status, found_count, created_count, updated_count, error_message
  from sync_runs order by started_at desc limit 3;

select name, address, external_id from properties;          -- 지금은 1건

select external_id, status, checkin_date, checkout_date, nights
  from reservations order by checkin_date desc;

select scheduled_date, status, needs_attention
  from cleaning_tasks order by scheduled_date desc;

select count(*) from reservation_private where guest_phone is not null;
select count(*) from reservation_finance where gross_amount > 0;
```

- **게스트 연락처가 호스트 본인 번호로 들어가 있지 않은지 확인할 것.** 가장 흔한 파싱 실수다.
- **두 번 연속 실행해 멱등성 확인** — `created_count=0`, `updated_count=전체`.

### 실측 결과 (2026-08-17)

| 항목 | 결과 |
|---|---|
| 수집 | 계약 5건 (1페이지) |
| 1회차 | created=5 / updated=0, 숙소 자동 생성 |
| 2·3회차 | **created=0 / updated=5** — 멱등성 확인 |
| `properties` | 1건, 키 = 지번 주소 |
| `cleaning_tasks` | 3건 — 취소 아닌 예약 3건의 퇴실일과 집합 일치 |
| `guest_phone` | 정상 3 / null 2(취소 건, 비공개) / 형식오류 0 |
| 호스트 번호 오염 | 0건 (원본의 임대인 블록과 대조) |
| launchd | `launchctl start` → exit 0, 로그 기록 |

**`cleaning_tasks` 가 예약 수보다 적은 것은 정상이다.** 트리거는 `status='cancelled'` 로 들어온
예약에 대해 조기 return 하므로 취소 건은 청소 태스크를 아예 만들지 않는다.

## 7. 이번 범위 밖 (다음 스펙)

- 알림 발송 (신규 예약·취소·`needs_attention` 발생 시 `notifications` 삽입 + 메일)
- 화면 (대시보드·달력·청소 보드·코멘트)
- 세션 만료 시 자동 재로그인 — 캡차·문자 인증 가능성이 있어 당분간 수동 재캡처

## 8. 운영 중 알아둘 것

- 세션은 언젠가 만료된다. 만료되면 `sync_runs` 에 `failed` 가 쌓이고 데이터는 안 건드려진다.
  그때 맥 앞에서 `npx tsx crawler/session.ts` 를 다시 돌리면 된다.
- 33m2 마크업이 바뀌면 파싱이 깨진다. 0건 안전장치 덕에 조용히 망가지지는 않는다 — 실패로 남으니
  `sync_runs` 만 가끔 보면 된다. 대시보드에 최근 동기화 상태를 띄우는 걸 권한다.
- 본인 계정의 본인 데이터를 가져오는 것이지만, 요청 간격을 두고 하루 두 번만 도는 선을 지킨다.

## 실제 구현 노트

초안대로만 짜면 다시 밟게 되는 것들이다. 전부 실제로 겪었다.

### 1. 헤드리스는 403 으로 차단된다 — UA 토큰을 지워야 한다

33m2 는 헤드리스 크로미움을 **HTTP 403 Forbidden** 으로 거부한다. 원인은 기본 User-Agent 의
`HeadlessChrome` 토큰이다. 5가지 구성을 시험해 특정했다:

| 구성 | 결과 |
|---|---|
| 헤드리스 (기본 UA) | ❌ 403 |
| 헤드리스 + 실제 UA | ✅ 200 |
| `channel:'chromium'` 신형 헤드리스 (기본 UA) | ❌ 403 |
| `channel:'chromium'` + 실제 UA | ✅ 200 |
| 헤디드(`headless:false`) | ✅ 200 |

즉 헤드리스 여부가 아니라 **UA 문자열**이 기준이다.

UA 를 하드코딩하면 크로미움이 올라갈 때마다 썩는다. 실제 UA 를 읽어 토큰만 지운다:

```ts
async function realUserAgent(browser: Browser): Promise<string> {
  const probe = await browser.newContext();
  try {
    const page = await probe.newPage();
    const ua = await page.evaluate(() => navigator.userAgent);
    return ua.replace(/HeadlessChrome/g, 'Chrome');
  } finally {
    await probe.close();
  }
}
```

### 2. `assertSession` 이 403 을 통과시켰다 — 모든 이동에서 상태 코드를 본다

세션 검사를 "로그인 페이지로 리다이렉트됐나 / 비밀번호 입력칸이 있나" 로만 했다.
**403 응답 본문은 `403 Forbidden` 13글자뿐이라 둘 다 해당이 없다.** 그래서 검사를 통과했고,
목록에서 링크를 못 찾아 "정상 접속했는데 계약이 0건" 으로 오인됐다.

모든 이동을 `navigate()` 로 묶고 4xx 를 즉시 실패시킨다. 상태 판정은 순수 함수로 떼어 테스트한다:

```ts
export function assertHttpOk(url: string, status: number): void {
  if (status === 401 || status === 403) throw new BlockedError(...);
  if (status >= 400) throw new Error(`${url} 요청 실패 (HTTP ${status})`);
}
```

`BlockedError` 는 `SessionExpiredError` 와 구분한다 — 대응이 다르다.
세션 만료면 재캡처, 차단이면 UA·IP 를 봐야 한다.

**이때 DB 가 오염되지 않은 건 5절 4번의 0건 안전장치 덕이다.** 그 장치가 없었으면
"계약 0건" 이 정상 동기화로 기록됐을 것이다.

### 3. 취소된 계약은 연락처 자리에 문장이 온다

```
연락처
취소된 계약은 연락처가 공개되지 않습니다.
```

이 문장을 그대로 `guest_phone` 에 저장하고 있었다. 화면에서 전화번호처럼 보이고 클릭 발신도 깨진다.
형식 검증을 통과하지 못하면 `null` 로 둔다. 원문은 `guestPhoneRaw` 와 `raw.detailText` 에 남는다.

```ts
export function normalizePhone(value: string | null): string | null {
  if (!value) return null;
  const m = value.match(/(0\d{1,2})[-\s]?(\d{3,4})[-\s]?(\d{4})/);
  return m ? `${m[1]}-${m[2]}-${m[3]}` : null;
}
```

### 4. 취소 건은 금액 합이 안 맞는 게 정상이다

`이용 금액 - 계약 수수료 ≠ 최종 정산 금액` 이면 파싱 오류를 의심하게 되는데, 취소 건은
환불 구조라서 원래 안 맞는다. 원본과 대조해 확인한 실제 예:

```
계약 A (전액 환불)          계약 B (임대료 90% 환불)
  이용 금액    350,000원      이용 금액        350,000원
  계약 수수료  -11,550원      임차인 환불 금액 -320,000원
  최종 정산 금액     0원      임대료 (90% 환불) -270,000원
                              관리비           -20,000원
                              청소비           -30,000원
                              정산 대상 금액    30,000원
                              계약 수수료         -990원
                              최종 정산 금액    29,010원
```

`이용 금액` / `계약 수수료` / `최종 정산 금액` 세 값만 컬럼으로 가고, 환불 항목들은 `raw` 에 남는다.
**합이 안 맞는다고 파서를 고치지 말 것.**

### 5. 실제 DOM 은 라벨과 값이 별도 줄이다

초안에는 `이름 김호스트` 처럼 한 줄로 실려 있었지만 실제로는 `이름` / `김호스트` 두 줄이다.
그리고 상단 네비게이션에 `임차인 모드로 전환` 이 있어서, `임차인` 을 부분일치로 찾으면
임차인 블록이 아니라 네비게이션을 집는다 — 그러면 게스트 정보가 통째로 `null` 이 된다.

- 라벨 검색은 **같은 줄의 값 → 없으면 다음 줄** 순서로 폴백한다
- 섹션 헤더(`임대인`/`임차인`)는 **정확 일치**로 찾는다
- 상세 페이지 단독으로는 상태 뱃지가 없다. 목록 카드 뱃지가 1순위인 이유다

### 6. 회귀 테스트

```bash
npm test    # tsx --test crawler/parse.test.ts
```

`crawler/fixtures/detail-pages.ts` 에 실제로 만난 형태 4종을 박아뒀다:
라벨/값 같은 줄, 라벨/값 별도 줄(실제 DOM), 취소 건(연락처 문장 + 환불 구조), 403 차단 본문.

**픽스처에 실제 게스트·호스트의 이름과 연락처를 넣지 않는다.** 전부 가짜 값이다.
숙소 주소는 `properties.external_id` 키라서 형태가 중요해 실제 값을 쓴다.

마크업이 바뀌어 파싱을 고칠 때는 픽스처를 먼저 추가하고 테스트가 깨지는 걸 확인한 뒤 고친다.

### 7. 기타

- `tsx` 는 이 프로젝트를 CJS 로 처리한다. **top-level await 을 쓰려면 `.mts` 확장자**가 필요하다.
  크롤러 본체는 `main()` 래퍼를 쓰므로 해당 없다.
- `run.sh` 는 `npx` 를 거치지 않고 tsx CLI 를 직접 부른다. launchd 환경에서 `npx` 해석이 불안정하다.
- npm 11 의 postinstall 차단 때문에 `esbuild` 승인이 안 돼 있으면 `tsx` 자체가 안 뜬다
