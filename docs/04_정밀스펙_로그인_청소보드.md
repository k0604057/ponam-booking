## 1. 목표

청소 담당이 폰으로 들어와서 **오늘 청소할 곳을 보고, 맡고, 완료 처리하고, 메모·사진을 남기는 것**까지
동작하게 만든다. 이것만 돼도 실사용을 시작할 수 있다.

## 2. 범위

**만든다**

- 로그인 / 로그아웃 / 승인 대기 화면
- 인증 미들웨어 (비로그인 → 로그인, 비활성 → 승인 대기)
- 하단 탭 앱 셸 (탭 4개, 청소만 구현)
- 청소 보드 (목록 · 맡기 · 완료 · 메모 · 사진)
- PWA 기본 (manifest, 아이콘, 홈 화면 추가)

**안 만든다** — 다음 스펙

- 대시보드, 예약 달력, 예약 상세, 정산, 설정, 코멘트 쓰레드, 알림, 멤버 초대

## 3. 인증

### 3.1 로그인 `src/app/(auth)/login/page.tsx`

- 이메일 + 비밀번호. `supabase.auth.signInWithPassword`
- 소셜 로그인 없음. 공개 가입 없음 (대시보드에서 꺼둠)
- 폼은 화면 중앙, 입력창 높이 48px 이상, `inputMode="email"`, `autoComplete="email" / "current-password"`
- 에러는 한국어로. `Invalid login credentials` 를 그대로 노출하지 말 것 →
  "이메일 또는 비밀번호가 맞지 않습니다"

### 3.2 승인 대기 `src/app/(auth)/pending/page.tsx`

**중요한 함정이다.** `profiles_select` 정책이 `is_member()` 기반이라, 비활성 계정은
**자기 자신의 profiles 행조차 0행으로 나온다.**

- 로그인은 됐는데 `profiles` 조회가 0행 = 승인 대기 상태다
- 이걸 오류나 무한 리다이렉트로 처리하면 안 된다. **"승인 대기 중" 화면**으로 보낸다
- 화면 문구: "가입 요청이 접수됐습니다. 호스트가 승인하면 이용할 수 있습니다."
- 로그아웃 버튼만 둔다

### 3.3 미들웨어 `src/middleware.ts`

```
- @supabase/ssr 로 세션 갱신 (getUser 호출 필수 — 이게 토큰을 refresh 한다)
- 세션 없음              → /login
- 세션 있고 profiles 0행 → /pending
- 세션 있고 활성         → 그대로 통과. /login·/pending 접근 시 /cleaning 으로
- matcher 에서 정적 파일·이미지·manifest·아이콘 제외
```

리다이렉트 루프를 반드시 손으로 확인할 것. `/login` → `/pending` → `/login` 이 가장 흔한 사고다.

### 3.4 세션 유지

청소 갈 때마다 다시 로그인하게 만들면 아무도 안 쓴다.

- 쿠키 기반 세션(`@supabase/ssr` 기본)을 쓰고, 브라우저를 닫아도 유지되게 한다
- 탭 포커스 복귀 시 자동 갱신되게 두고, 만료로 튕기면 로그인 후 **원래 보던 화면으로 복귀**시킨다
  (`?next=` 파라미터)

## 4. 앱 셸 `src/app/(app)/layout.tsx`

하단 고정 탭. 상단 햄버거 금지.

| 탭 | 경로 | 이번 스펙 |
|---|---|---|
| 청소 | `/cleaning` | **구현** (기본 진입) |
| 달력 | `/calendar` | "준비 중" placeholder |
| 예약 | `/reservations` | "준비 중" placeholder |
| 더보기 | `/more` | 내 정보 + 로그아웃만 |

- 탭 높이 56px + `env(safe-area-inset-bottom)` 만큼 하단 패딩 (아이폰 홈 인디케이터)
- 아이콘 + 라벨. 아이콘만 두지 않는다 — 나이 드신 분들이 못 알아본다
- 콘텐츠 영역에도 하단 여백을 줘서 탭에 가려지지 않게 한다
- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`

역할에 따라 탭을 숨기지 않는다. 눌렀을 때 권한이 없으면 그때 안내한다.
(RLS가 이미 막고 있으므로 보안 문제가 아니라 UX 문제다)

## 5. 청소 보드 `src/app/(app)/cleaning/page.tsx`

### 5.1 데이터

Server Component 에서 조회한다.

```
cleaning_tasks
  + properties (name, color)
  + reservations (checkin_date, checkout_date, public_note)  ← source_reservation_id 조인
  + assignee: profiles (name)
  + completed_by: profiles (name)
where status <> 'skipped'
  and scheduled_date between (오늘 - 14일) and (오늘 + 30일)
order by scheduled_date
```

`skipped`(취소된 예약)는 기본으로 감춘다. "취소된 건 보기" 토글로 볼 수 있게만 한다.

### 5.2 그룹핑

날짜 기준으로 섹션을 나눈다. 이 순서 그대로:

1. **밀린 청소** — `scheduled_date < 오늘` 이고 `status = 'pending'`. 빨간 강조
2. **오늘**
3. **내일**
4. **이번 주**
5. **다음 주 이후**

각 섹션은 비어 있으면 통째로 숨긴다. 전부 비면 "예정된 청소가 없습니다".

### 5.3 카드

한 칼럼 카드. 표를 쓰지 않는다.

- 날짜 (`8/23 (토)`) + 숙소 이름 (숙소 색상 점)
- **당일 턴오버 경고** — 같은 숙소에서 이 퇴실일에 다른 예약이 입실하면
  "당일 입실 있음" 배지를 눈에 띄게. 청소 담당에게 가장 중요한 정보다
- 상태 배지: `청소전` / `청소완료`
- `needs_attention = true` 면 "일정 변경됨 확인 필요" 배지
- 담당자 이름 (없으면 "미배정")
- 완료된 건은 완료자 이름과 시각
- 예약의 `public_note` 가 있으면 표시
- 메모(`note`)가 있으면 표시

**금액과 게스트 이름·연락처는 절대 넣지 않는다.** 청소 담당은 볼 수 없는 정보고,
RLS상 애초에 조회되지도 않는다.

### 5.4 동작

세 가지 액션. **전부 RPC 로 호출한다.** `cleaning` 역할은 `cleaning_tasks` 를 직접 UPDATE 할 수 없다.

```ts
await supabase.rpc('claim_cleaning_task', { p_task_id: id });                     // 맡기
await supabase.rpc('claim_cleaning_task', { p_task_id: id, p_claim: false });     // 놓기
await supabase.rpc('set_cleaning_done',   { p_task_id: id, p_note: '수건 부족' }); // 완료
await supabase.rpc('set_cleaning_done',   { p_task_id: id, p_done: false });      // 완료 취소
```

- **청소완료 버튼**: 카드 안이 아니라, 카드를 열었을 때 **화면 하단 고정**. 높이 52px 이상, 폭 전체
- 완료는 되돌릴 수 있게 한다. 다만 되돌리면 `needs_attention` 이 켜지므로
  "완료를 취소하면 관리자에게 표시됩니다" 를 한 줄 안내
- 메모는 2000자 제한(RPC 가 거부한다). 입력창에서 미리 막고 남은 글자수를 보여준다
- 낙관적 업데이트를 쓰되 **실패하면 원래 상태로 되돌리고 에러를 보여준다.**
  RPC 가 던지는 한국어 예외 메시지를 그대로 노출해도 된다
- 액션 후 `router.refresh()` 로 서버 데이터를 다시 읽는다

### 5.5 사진

- `<input type="file" accept="image/*" capture="environment" multiple>` — 카메라 바로 열기
- 업로드 전 **클라이언트에서 리사이즈**: 긴 변 1600px, JPEG 품질 0.8.
  폰 원본은 3~5MB라 그대로 올리면 느리고 스토리지가 금방 찬다
- 업로드 경로: `cleaning-photos/{task_id}/{crypto.randomUUID()}.jpg`
- 업로드 성공 후 `cleaning_photos` 에 insert (`cleaning_task_id`, `storage_path`, `uploaded_by = 내 uid`)
- 표시는 `createSignedUrl` 로. 버킷이 비공개라 public URL 은 안 된다. 만료 1시간
- 업로드 중 진행 표시. 실패 시 재시도 버튼

RLS 제약 — **자기가 맡은 건이나 미배정 건에만** 사진을 붙일 수 있고, `skipped` 건에는 못 붙인다.

## 실제 구현 노트

### 1. '지난 청소' 섹션을 하나 더 뒀다

스펙의 섹션은 5개인데, 조회 범위가 **오늘-14일**부터라 "지난 날짜인데 `pending` 이 아닌" 건이
반드시 생긴다(완료된 지난 청소). 5개 섹션 어디에도 안 들어가서 화면에서 사라진다.

`밀린 청소`(빨간 강조)에 섞으면 안 되므로 맨 뒤에 **`지난 청소`** 를 추가했다.
섹션 규칙은 `src/lib/cleaning.ts` 의 `sectionOf()` 한 곳에 모아 뒀다.

### 2. 날짜는 문자열로만 비교한다

`YYYY-MM-DD` 를 `Date` 로 바꿔 비교하면 서버 타임존에 따라 하루가 밀린다.
서버가 UTC 여도 사용자는 서울에 있다. 오늘 날짜는 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })`
로 뽑고, 날짜 덧셈은 `Date.UTC` 로만 한다.

### 3. 당일 턴오버는 별도 질의가 필요하다

청소 건에 붙은 예약은 **퇴실하는** 예약이다. 같은 날 **입실하는** 예약은 다른 행이라
조인으로 안 나온다. `reservations` 를 `checkin_date` 범위로 한 번 더 읽어
`(property_id, 날짜)` 맵을 만들어 맞춘다.

`checkin_time` 은 크롤러가 `null` 로 두므로 배지는 보통 "당일 입실 있음" 까지만 나온다.
시각이 있으면 뒤에 붙인다.

### 4. 카드를 여는 UI 는 전체 화면 시트로 했다

"청소완료 버튼을 화면 하단 고정" 인데, 카드를 인라인으로 펼치면 여러 장이 열렸을 때
하단 고정 버튼이 여러 개 겹친다. 전체 화면 시트로 만들면 한 번에 하나만 열리는 게 구조로 보장된다.
하단 탭(z-50) 보다 위(z-60)에 뜬다.

### 5. 아이콘 글자는 라틴 문자로 했다

`next/og` 가 기본 번들하는 폰트에 **한글 글리프가 없다.** "포남" 을 쓰면 두부(□□)로 렌더된다.
시스템 한글 폰트를 읽어 넣을 수는 있지만 빌드 환경(리눅스)에 그 폰트가 없어 더 위험하다.
그래서 `PN` 으로 했다. 제대로 된 아이콘이 준비되면 `src/lib/icon.tsx` 만 갈아끼우면 된다.

아이콘은 `next/og` 라우트 핸들러(`src/app/icon-192.png/route.tsx` 등)로 만들고
`export const dynamic = 'force-static'` 을 붙여 빌드 시점에 굽는다. manifest 가 참조할
**안정적인 URL** 이 필요해서 `app/icon.tsx` 관례(`/icon?<hash>`) 대신 이 방식을 썼다.

### 6. 미들웨어 matcher 에서 아이콘·manifest 를 빼야 한다

빼지 않으면 홈 화면 추가 시 아이콘 요청이 `/login` 으로 리다이렉트돼 아이콘이 안 나온다.
검증: 비로그인 상태로 `/manifest.webmanifest`, `/icon-192.png`, `/apple-icon.png` 가 200 이어야 한다.

### 7. `/` 는 `/cleaning` 으로 보낸다

대시보드는 다음 스펙이라 `/` 에 놓인 placeholder 가 무의미하다. 활성 멤버가 `/` 로 오면
홈(`/cleaning`)으로 보낸다. 대시보드를 만들면 이 규칙을 지운다.

**렌더링·리다이렉트 — 실제 세션 쿠키로 확인.**

- 비로그인: 모든 보호 경로 → `/login?next=…`, `/login` 은 200 (루프 없음)
- 활성 멤버: `/` `/login` `/pending` → `/cleaning`, `/cleaning` `/more` 는 200
- 비활성: 모든 경로 → `/pending`, `/pending` 은 200 (루프 없음)
- **`/cleaning` · `/more` HTML 전체(스크립트 페이로드 포함)에 금액·게스트 이름·연락처 0건**

검증에 쓴 테스트 계정과 데이터는 전부 지웠고, 손댄 청소 건은 원래 상태로 복원했다.

### 9. 아직 안 한 것

- **7.3 폰 실기기 확인** — 배포 URL 이 있어야 한다. 시뮬레이터로는 안 잡히는 항목들이다
- 사진 업로드의 **스토리지 실제 업로드 경로**는 브라우저에서만 돌아간다
  (`createImageBitmap`·`canvas`). RLS 정책 검증은 DB 행 insert 로 대신했다
