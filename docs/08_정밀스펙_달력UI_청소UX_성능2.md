## 1. 탭 순서 · 진입 화면

하단 탭은 **달력 · 예약 · 청소 · 더보기** 순.

진입 화면은 역할에 따라 다르다. 첫 탭으로 무조건 보내면 청소 담당이 매번 한 번씩 더 눌러야 한다.

```
cleaning                            → /cleaning
그 외(owner·reservation·settlement) → /calendar
```

`/` 는 위 규칙대로 리다이렉트한다. **판단은 미들웨어 한 곳에서만** 한다 —
로그인 폼·초대 수락은 역할을 모르므로 `/` 로 보내고 미들웨어가 정한다.

## 2. 달력 — 월 그리드

- 7열, 월~일. 상단에 `2026년 8월` + 좌우 이동 + `오늘`
- 오늘 칸은 테두리로 강조
- 각 칸에 그날 걸쳐 있는 예약을 **막대**로. 최대 2개, 나머지는 `+n`
- 청소는 칸 하단에 점 — 미완료=채운 점, 완료=빈 점, `needs_attention`=느낌표
- **날짜를 누르면 그리드 아래에 상세가 펼쳐진다.** 새 화면으로 넘기지 않는다
- 데이터는 **표시 중인 달의 앞뒤 1개월까지 한 번에** 받아둔다.
  그 범위 안에서 달을 넘길 때는 서버를 치지 않는다
- 조회 조건은 `checkout_date >= 시작 and checkin_date <= 끝`

## 3. 예약 상태 색상

**딱지만으로는 구분이 안 된다.** 박스 전체를 색으로 구분하고, 달력 막대와 목록 카드가
**같은 상수**를 쓴다 — `src/lib/status.ts` 의 `RESERVATION_STATUS_STYLE`.

| 상태 | 판정 | 색 |
|---|---|---|
| 거주중 | `confirmed` 이고 `checkin <= 오늘 <= checkout` | 초록 (배경 + 좌측 띠) |
| 예정 | `confirmed` 이고 `checkin > 오늘` | 노랑 |
| 종료 | `completed` 이거나 `checkout < 오늘` | 회색 + **전체 흐리게(opacity 55%)** |
| 취소 | `cancelled` | 회색 + 취소선. 달력에서는 기본 숨김, 토글로만 |

- 종료 건은 글자·배지·금액까지 전부 흐리게. 배경만 회색으로 두면 여전히 눈에 걸린다
- **색만으로 구분하지 않는다.** 배지 텍스트를 항상 같이 둔다

## 4. 청소 UX

### 4.1 "놓기" 제거 · 담당 없이도 완료

담당 지정은 부가 기능이지 완료의 전제 조건이 아니다.

- `담당: 미지정` + 작은 `[내가 맡기]`. 내가 맡았으면 `[담당 해제]` (— "놓기" 라는 말은 쓰지 않는다)
- 남이 맡았으면 이름만 표시하고 버튼 없음
- **맡기를 눌러도 날짜 선택 시트를 자동으로 띄우지 않는다.** 맡기와 날짜는 별개다
- `청소 예정일: 미정 [날짜 선택]` 을 따로 둔다

### 4.2 완료 후 흐름

```
[청소완료] → 성공 → 토스트("청소 완료되었습니다") → 시트 닫고 목록으로
```

- 토스트는 화면을 막지 않고 2초 뒤 사라진다. 확인 버튼을 누르게 하면 손이 한 번 더 간다
- **실패하면 시트를 닫지 않는다.** 에러를 시트 안에 보여준다
- 완료 취소는 시트를 닫지 않는다 (되돌리고 바로 다시 볼 일이 많다)

## 5. 성능 2차

`experimental.staleTimes.dynamic = 30` — 30초 안에 다시 누른 탭은 서버 왕복 없이 뜬다.
변경 후에는 이미 `router.refresh()` 를 부르므로 오래된 데이터가 남지 않는다.

## 측정 결과 (2026-08-18, 배포 환경)

지난번(스펙 #7) 측정은 **맥미니 로컬 서버**를 잰 것이라 사용자가 겪는 경로가 아니었다.
이번엔 **배포 URL** 기준으로 다시 쟀다.

### 리전 판정 — **함수가 미국(iad1)이다**

Vercel 응답 헤더 `x-vercel-id` 가 `<엣지>::<함수 리전>::<id>` 형식이라 로그 없이 판별된다.

| 요청 | `x-vercel-id` | 해석 |
|---|---|---|
| `/login` (정적, 세션 없음) | `icn1::…` | 서울 엣지에서 바로 서빙 |
| `/cleaning` (동적, 세션 있음) | **`icn1::iad1::…`** | 서울 엣지 → **미국(iad1) 함수** |

**코드의 `preferredRegion = 'icn1'` 은 먹지 않았다.** 재배포 후에도 `icn1::iad1` 그대로다 —
대시보드의 Function Region 설정이 우선한다.

### 화면별 TTFB (배포 URL, 12회 표본)

| 화면 | 중앙값 | p25 | 최소 | 최대 |
|---|---|---|---|---|
| `/calendar` | 546ms | 529ms | 514ms | 941ms |
| `/cleaning` | 527ms | 517ms | 508ms | 955ms |
| `/reservations` | 702ms | 554ms | 523ms | 747ms |
| `/more` | 567ms | — | 530ms | 988ms |
| **`/login`** (DB 왕복 없음, 엣지 서빙) | **30~38ms** | | | |

### 어디서 시간이 가는가

| 경로 | 시간 |
|---|---|
| 서울 엣지에서 정적 서빙 (`/login`) | **~35ms** |
| 로컬(서울↔서울) 동적 렌더 — 스펙 #7 실측 | **~77ms** |
| 배포(서울→미국 함수→서울 DB) 동적 렌더 | **~510ms 바닥** |

**차이 약 450ms 가 전부 태평양 왕복이다.** 쿼리를 더 줄여도 이 바닥은 내려가지 않는다.
왕복 횟수를 이미 6회 → 3회로 줄여둔 상태라, 남은 개선은 리전 하나뿐이다.

### 콜드 스타트

첫 요청이 유독 느리다. `/cleaning` 첫 요청 **1,598ms** vs 이후 중앙값 **527ms**.
한동안 안 쓰다가 열면 이만큼 더 걸린다. 코드로는 못 줄인다.

### 번들 크기 — **200KB 초과, 보고 대상**

`/login` 이 실제로 로드하는 스크립트 9개 합계 **235.5 KB (gzip)**.
대부분 React/Next 런타임과 `@supabase/supabase-js` 다 —
클라이언트 컴포넌트(로그인 폼·청소 시트·멤버 관리)가 Supabase 브라우저 클라이언트를 쓴다.

지금 병목은 아니다(태평양 왕복이 450ms인데 번들은 캐시된다). 리전을 고친 뒤에도 느리면 그때 본다.

### `staleTimes` 효과는 curl 로 잴 수 없다

클라이언트 라우터 캐시라 **브라우저에서 탭을 다시 눌렀을 때** 요청 자체가 안 나가는 것이 효과다.
curl 은 매번 새 요청이라 이 절약분이 잡히지 않는다. 설정이 적용된 것만 확인했고,
**체감 비교는 폰/브라우저에서 사람이 해야 한다.**

## 실제 구현 노트

### 1. `preferredRegion` 은 대시보드를 이기지 못한다

스펙 5.1 이 의심한 그대로였다. 코드에 넣고 재배포해도 `x-vercel-id` 는 `icn1::iad1` 이다.
**대시보드 → Settings → Functions → Function Region 을 Seoul(icn1) 로 바꿔야 한다.**
그 전까지는 어떤 코드 최적화도 450ms 바닥을 못 넘는다.

### 2. 진입 화면 판단을 한 곳에 모았다

로그인 폼과 초대 수락은 역할을 모른다. 각자 `/cleaning` 으로 보내고 있었는데,
역할별 분기가 생기면서 세 군데가 어긋날 여지가 생겼다.
전부 `/` 로 보내고 **미들웨어가 `homeFor(role)` 로 정한다.** PWA `start_url` 도 `/` 로 바꿨다.

### 3. 달력 데이터는 ±1개월을 미리 받는다

월 이동마다 서버를 치면 왕복이 그대로 붙는다(지금은 500ms).
서버가 `?m=YYYY-MM` 기준 앞뒤 1개월을 한 번에 주고, 클라이언트는 그 범위 안에서 상태만 바꾼다.
범위를 벗어날 때만 `router.push` 로 서버를 친다.

### 4. 완료자는 '최초 완료자' 가 유지된다

`set_cleaning_done` 이 `completed_by = coalesce(completed_by, auth.uid())` 로 되어 있다.
완료 → 취소 → 다른 사람이 완료 하면 **처음 완료한 사람이 그대로 남는다.**
마이그레이션에 "재호출로 완료자를 갈아치울 수 없게" 라고 의도로 적혀 있어 그대로 뒀다.
`completed_by` 가 비어 있는 건에서는 정상적으로 기록된다(확인함).
청소 건수 집계에 영향이 있으므로, 바꾸려면 마이그레이션이 필요하다 — 먼저 보고할 것.
